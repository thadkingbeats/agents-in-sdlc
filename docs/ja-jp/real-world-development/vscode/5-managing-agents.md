GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。開発者のマシン上でリアルタイムに作業するため、VS Code の Copilot Chat ではツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を採用または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして採用します。
- セッションの途中でエージェントに指示し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントが、ハイ コントラスト モードを実装しています。作業中にデザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライト モードの切り替えも追加します。新しい会話を始める代わりに、現在のセッションに追加の作業を依頼します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集など、各手順が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取りと編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインに表示されます。
   - **Keep** を選択して変更を採用します。
   - **Undo** を選択して変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** の表示を開くと、セッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ツール呼び出しで許可が必要な場合 (ターミナル コマンドの実行など)、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。変更内容をまとめた最終メッセージが表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けることで、エージェントは変更したコンポーネント、スタイルの方針、設定を local storage に保存する方法を引き継げます。

1. Copilot Chat の入力欄に、次のフォローアップ プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントがすでに加えた変更を調べ、ライト モードの追加を提案します。
3. 追加された編集を確認し、各差分で **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合 (例: 切り替え UI を意図しない方法でリファクタリングする場合) は、チャット入力欄の隣にある **Stop** ボタンで停止し、明確な追加プロンプトを送ります。

> [!TIP]
> 実行中のセッションに指示する方が、最初からやり直すより速く進められます。フォローアップ プロンプトで、調整を依頼する (「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」)、方針を修正する (「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを追加する」)、範囲を広げる (「両方の切り替えにキーボード ショートカットも追加する」) ことができます。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. いくつかの変更ファイルを開き、差分を確認します。カスタム エージェントが案内したアクセシビリティのパターン (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage による設定の保存) が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更を stage してコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で実行中のセッションを監視して案内し、各ファイル編集を確認して採用または取り消し、コンテキストを保ったままフォローアップ プロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または取り消しました。
- 実行中のセッションにフォローアップを送り、作業を調整しました。

次のレッスンでは、アクセシビリティの変更をプルリクエストとして公開し、このラボを通してローカルのカスタム エージェントが行った変更をレビューします。
